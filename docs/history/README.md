# Historical NASolve documentation

Documents in this directory describe earlier implementation, validation, or
planning states.

They are retained for forensic use by future developers and agents: they may
explain what was tried, what failed, and why a later design exists.

They are not current instructions. Branch names, commands, test counts, paths,
limitations, and "next steps" may have been superseded.

For current truth, read:

1. `../../README.md`
2. `../README.md`
3. `../architecture.md`
4. `../development-handoff.md`
5. the relevant active subsystem document

Use history to explain current behavior, not to override it automatically.
